# 体験版 v1.0「黒雨の城下町」— 調査・設計メモ

## 1. 現状調査（STEP 0）の結論

`samurai-mobile` の `src/` は参考リポジトリ **SamuraiThirdPersonTemplateThreeJS と完全に同一**（`diff -rq` で差分なし）。
つまり「ゲーム」ではなく、PC向けの高品質な三人称テックデモだった。

| 区分 | 項目 | 判定・対応 |
| --- | --- | --- |
| 完成している（そのまま活用） | 描画基盤（Renderer / ポスト / 霧 / 空 / 地形 / 影） | 設定値のみ変更して流用 |
| | キャラ読込・Mixamoリターゲット・移動ブレンド（`CharacterController` / `Locomotion`） | 流用。リターゲット処理を `animation/retarget.js` に共通化し敵にも使用 |
| | モーションワープ攻撃（`Attack`） | **拡張して全技の基盤に**（クリップ区間・多段ヒット・予備動作減速・release） |
| | ラグドール死亡・胴体切断・血しぶき・ディゾルブ（`Enemy` / `Ragdoll` / `BloodBurst`） | 撃破演出としてそのまま活用 |
| | ヒットストップ・カメラ振動 | 流用（スロー演出を追加） |
| | 天罰の拳（`Judgement`） | **奥義**として再利用（朱・金に配色変更、範囲攻撃化） |
| | 衝撃波・土煙・火花（`ShockRing` / `DustBurst` / `BladeImpact`） | ヒット・パリィ・叩きつけ演出に再利用 |
| | 装備システム（刀の装着） | 流用（ゲームでは刀のみ） |
| 改善が必要 | 操作（PCキーボードのみ） | `GameInput` + `TouchControls` を新設（仮想スティック/ボタン/カメラスワイプ/タップロック） |
| | 敵（棒立ち・一撃死） | `EnemyAgent` でHP/体幹/怯み/ダウン/攻撃を追加。既存Enemyは後方互換フックのみ |
| | アセット容量（初回約65MB） | 約21MBへ削減（下記） |
| | 描画負荷（4096²影・HDR等） | 品質ティア＋動的解像度 |
| 不足していた | HP・ガード・パリィ・回避・コンボ・魔法・ロックオン・敵AI・ボス・ステージ・進行・UI・音 | すべて新規（`src/game/`） |
| 不要・重複（体験版では未使用） | 飛行＋刀の嵐、影分身、装備スタジオ、エディタ | **削除せず** `?dev` モードに温存（ゲームからは呼ばない） |
| | `models/environment/tree.glb`（どこからも未参照） | 削除はしていない（要判断） |

追加モデル: 弓「Bow and Arrow」(Amatsukast / Sketchfab) は **CC BY-NC-SA 4.0＝非商用限定**。体験版・非商用公開は可、販売する場合は差し替え必須。魔法発動時に `game/combat/BowRig.js` が弓を構えさせ（胴の半身ひねり＋両腕2ボーンIK）、矢の先端から魔法を放つ。

新規ランタイム依存は **ゼロ**（three / lil-gui のまま）。テクスチャ・音はすべて実行時生成でライセンス問題なし。

## 3. 体験版の構成

```
src/game/
  Game.js              全体ハブ（ダメージ処理・時間制御・ロックオン・カメラ補助・画面遷移）
  Flow.js              進行スクリプト（11ビート・チェックポイント・拾得物・チュートリアル）
  GameInput.js         キーボード/マウス/タッチを同一インターフェースに
  combat/PlayerCombat  5段コンボ・居合(長押し)・回避(見切り)・ガード/パリィ・反撃・処刑・魔法・奥義
  combat/PoseLayer     ガード・回避・被弾の姿勢レイヤー
  ai/EnemyAgent        敵1体の思考とHP/体幹（索敵・間合い・予兆・攻撃・怯み・ダウン・崩れ・凍結）
  ai/AIDirector        攻撃権トークン・攻撃間隔・分離・遠距離の影LOD・処理間引き
  ai/EnemyGear         武器・笠・角・目（プリミティブ、型ごとに共有）
  boss/Rasetsu         黒角鬼・羅刹（3フェーズ・燃える地面・必殺「羅刹天」・専用処刑）
  magic/Magic          火球/雷撃/氷弾・状態異常・属性反応・弓妖の矢（パリィで反射可）
  fx/                  剣閃トレイル・発光パーティクル・稲妻リボン・既存VFXの集約
  world/               ステージ（城下町/廃神社/城門）・雨・手続きテクスチャ・夜の環境マップ
  audio/Sound          WebAudio手続き生成（雨・金属音・咆哮・太鼓BGM・雷鳴）
  ui/                  和風HUD・各種画面・CSS
  data/                武器・属性/反応・敵タイプ・ゲーム用設定（すべてデータ駆動）
```

### 拡張性
- **武器**: `data/weapons.js` に双剣・大剣・槍・弓・斧・鎖鎌・手裏剣・杖・魔導武器の枠を定義済み（`available:false`）。同じ形式でコンボ/強攻撃/回避値を書けば `PlayerCombat` は無変更で動く。
- **属性**: `data/elements.js` に8属性（火雷氷風水土光闇）を定義済み。呪文と反応表を追加するだけで拡張可能。
- **敵**: `data/enemies.js` にエントリを足すだけ（同一リグ＋リターゲット）。

## 4. スマホ最適化

| 対策 | 内容 |
| --- | --- |
| 品質ティア | low/mid/high を自動判定（`?q=low` で強制）。影解像度・ブルーム・雨量・落ち葉・霧・ランタン光源数・敵上限・AI間引きを切替 |
| 動的解像度 | 実測フレーム時間で描画解像度と敵上限を自動調整（`?dyn=0` で無効） |
| 描画呼び出し | ステージ全体をマテリアル単位で結合（約15ドロー）。雨・火花・光はGPU計算の1ドロー |
| 影 | 敵は近距離のみ影を落とす（lowでは敵影なし） |
| ライト | ランタン光源は少数のPointLightをプレイヤー近傍へ付け替え（シェーダ再コンパイルなし） |
| アセット | 初回DL 約65MB → **約21MB**（FBX埋込画像除去 21.8→4.3MB、テクスチャJPEG化 24.5→7.5MB、HDR/月テクスチャ不使用、重複マップ縮小） |

FBXの埋込画像除去は `node scripts/strip-fbx-media.mjs in.fbx out.fbx` で再実行可能。

## 5. 検証方法

ヘッドレスChromium（SwiftShader）で以下を自動確認済み。
- ビルド成功・コンソールエラーなし
- 全11ビートの通し（城下町→赤鬼→雷取得→百鬼夜行→忍妖の奇襲→境内→氷取得→城門→羅刹3フェーズ→処刑→リザルト）
- 死亡→討死画面→再挑戦（チェックポイント復帰）、ポーズ→音量→再開
- コンボ5段遷移、崩し→処刑、魔法3種の命中、パリィ判定
- 開発モード `?dev` が従来通り動作

`App#simulate(seconds)` で描画なしに時間を進められる（自動テスト用）。

## 6. 既知の制限・次の作業候補

- 実機（iPhone/Android）での60fps・操作感の最終確認（ヘッドレス環境はソフトウェア描画のため実フレームレートは未測定）
- 敵メッシュは単一のMixamoマネキン（色・装備・体格で差別化）。専用モデル導入で見栄えが大きく向上する
- 回避・被弾・ガード専用モーションが無いため既存クリップの一部を流用。専用モーション追加で手触りがさらに向上
- iOS Safari はフルスクリーン/向きロックAPI非対応（ホーム画面追加で全画面表示）
